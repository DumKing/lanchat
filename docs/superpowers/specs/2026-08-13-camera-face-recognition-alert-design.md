# 摄像头人脸识别与自动告警设计

## 目标

在现有"摄像头人脸出现检测"（YuNet 存在检测 + 匿名告警）基础上，增加人脸识别能力：将摄像头画面中检测到的人脸与本机已配置的人员参考照片进行特征比对，命中后自动产生**具名告警**，并介入桌宠告警与外部群机器人推送，且与普通告警（狼来了）明确区分。

## 范围

- 内置 OpenCV Zoo SFace 人脸识别模型（MIT），复用现有模型清单 SHA-256 校验与 ort 推理链路。
- YuNet 输出升级为多人脸解码（锚框解码 + NMS），一帧内多张人脸分别识别。
- 人员录入（上传照片 / 摄像头拍照）时提取 128 维特征向量并落库；每人一张参考照片。
- 识别命中后生成具名告警（`source_kind = "camera_face"`），复用现有告警门限（`minConfidence` / `consecutiveHits` / `cooldownSeconds`），**不新增相似度配置项**：匹配置信度 = 余弦相似度 × 100。
- 有已启用且特征可用的人员时进入"仅命中告警"模式：陌生人不告警。
- **取消匿名"检测到人脸"告警**：不再产生任何 `camera_face_presence` 告警事件与数据；未录入人员或识别模型不可用时也不产生告警，仅在设置页显示错误提示。
- 识别告警驱动桌宠 Alert 状态并触发外部推送（企业微信 / 钉钉），与狼来了告警在队列、文案、推送格式上区分。

不包含：每人多张参考照片、按人员单独配置阈值、识别特征跨设备同步、识别模型在线下载、非 Windows 平台的摄像头采集（维持现状）。

## 现状与缺口

| 能力 | 现状 | 本次改动 |
| --- | --- | --- |
| 人脸检测 | YuNet ONNX，只取最强锚框分数判断"有人脸" | 解码全部锚框 + NMS，输出多张人脸框与 5 关键点 |
| 人脸识别 | 无；README 明确"不与本地照片比对" | 新增 SFace 特征提取与余弦相似度比对 |
| 人员配置 | `face_people` 表 + 上传/拍照录入，仅存照片 | 录入时提取特征向量，新增 `embedding` 列 |
| 告警 | 匿名 `camera_face_presence` 告警 | 取消匿名告警，仅保留具名 `camera_face` 告警 |
| 告警门限 | `accept_match`（阈值/连击/冷却） | 复用，key 改为按 `personId` 独立计数 |
| 桌宠/外部推送 | 人脸告警不介入 | 识别告警介入桌宠 Alert 与外部推送，并与狼来了区分 |

## 模型资源与校验

`src-tauri/resources/object-models/manifest.json` 从 `schemaVersion: 1` 升级为 2：

```json
{
  "schemaVersion": 2,
  "modelVersion": "opencv-zoo-yunet-sface-2026.08",
  "detector": { "file": "presence-detector.onnx", "sha256": "..." },
  "recognizer": { "file": "face-recognizer.onnx", "sha256": "..." }
}
```

- `recognizer` 为 OpenCV Zoo SFace 模型（输入 112×112 对齐人脸，输出 128 维特征），随安装包分发，SHA-256 校验规则与 detector 一致。
- 兼容旧清单：缺少 `recognizer` 时按"仅存在检测"运行，识别功能在状态中报告"识别模型未安装"。
- `FaceMonitorStatus` 新增 `recognizer_ready: bool`；识别模型缺失、校验失败或加载失败时给出中文错误原因，设置页展示。

## Rust 识别管线（扩展 `face_monitor.rs`）

现有 `analyze_frame` 只回答"是否有人脸"，升级为 `analyze_frame_full`，返回一帧的完整识别结果：

1. **多人脸解码**：解码 YuNet 三个步长（8/16/32）的全部锚框（bbox 回归 + 5 关键点），置信度过滤 + NMS，输出 0..N 张人脸。现有"最强分数 ≥ 0.60"的存在判断以解码结果为准。
2. **对齐裁剪**：按 5 关键点（双眼、鼻尖、嘴角）做仿射对齐，裁剪 112×112 RGB 人脸。
3. **特征提取**：SFace 推理，输出 128 维向量并 L2 归一化。
4. **比对**：与所有"已启用且特征可用"的人员计算余弦相似度，`confidence = round(相似度 × 100)`，并 clamp 到 0..100（余弦相似度可能为负，避免 `u8` 溢出）。
5. **门限**：每个命中人员以 `personId` 为 key 走现有 `accept_match`（`min_confidence` / `consecutive_hits` / `cooldown_seconds`），各人员独立连击计数与冷却。

`submit_face_monitor_frame` 命令改为调用 `analyze_frame_full`。参考照片特征提取复用同一 SFace 会话与对齐逻辑（`extract_embedding` 公开方法）。

推理仍然单帧串行（`busy` 门闩），采样帧只进内存，推理结束即释放。

## 特征存储与人员录入

`face_people` 表新增两列（`ensure_column` 迁移）：

- `embedding BLOB`：128 维 f32 小端字节。
- `embedding_model_version TEXT`：提取时的 `modelVersion`。

规则：

- **录入时提取**：`create_local_face_person` 保存照片后立即提取特征；照片中检测不到人脸则录入失败，报错"参考照片中未检测到人脸"。
- **版本失效**：加载人员时若 `embedding_model_version` 与当前模型版本不一致，用照片路径重新提取；照片不可读时清空特征并标记"特征不可用"，该人员不参与比对但保留记录。
- **远端下发人员**：照片路径在本机不可读时只存储不参与识别，与现状一致，不新增协议字段（`FacePersonPolicyFrame` 不变）。
- 删除人员（`delete_face_person_local`）连带失效特征，无需额外清理。

## 告警模式与降级

- **识别模式**：本机存在 ≥1 个"已启用且特征可用"的人员时生效。只对命中人员发具名告警：`source_kind = "camera_face"`，`person_id` / `person_name` 为真实人员，`confidence` 为匹配置信度。未匹配的陌生人脸**不告警**。
- **无告警场景**：无启用人员或识别模型不可用时，设置页状态区显示明确错误提示（如"请先录入识别人员""识别模型未安装"）；监控继续运行检测但**不产生任何告警事件与数据**。
- **取消匿名告警**：原 `camera_face_presence` 匿名告警不再产生，不写入新事件与数据；数据库中历史记录照常展示。
- **多人命中**：一帧内多个人员分别命中时，各自生成告警，受各自连击与冷却约束。
- 告警落库、局域网广播、`camera_face_alert_received` 事件、反馈链路复用现有实现；唯一告警类型即识别告警，不新增类型字段。

## 桌宠与外部推送介入（与普通告警区分）

### 区分机制

三类告警事件互不混淆：

| 类型 | 标识 | 队列 |
| --- | --- | --- |
| 狼来了 | `QuickAlertFrame` | `alertRecords`（不变） |
| 人脸识别命中 | `source_kind = "camera_face"` | `cameraFaceAlerts` |

匿名存在告警已取消，不再产生新事件；历史 `camera_face_presence` 记录仍在列表中展示。识别告警不进入狼来了队列，反馈与可信度统计不污染狼来了。

### 桌宠

- 本机产生或收到识别告警（`camera_face`）时，桌宠进入 Alert 状态，复用现有 Alert clips、闪烁、详情窗口与真实/虚假反馈链路。
- 桌宠告警标题为 **"【人脸识别】检测到 {人员名}"**，详情窗口显示人员名、置信度、来源设备，与狼来了文案区分。

### 外部推送

- 识别告警的**产生端**（监控设备）在告警生成后，若桌宠设置 `external_push_enabled` 开启，向所有已启用的 webhook 推送。
- 推送文案使用专用格式，不复用狼来了模板：
  `[人脸识别告警] 检测到 {人员名} · 置信度 {n}% · 来源：{设备昵称}({IP}) · {时间}`；`mention_all` 生效。
- 自动告警无"发送人可信度"概念，不走 `external_push_min_credibility` 阈值；超管锁定逻辑保持不变。
- 推送走**独立渲染与发送路径**：新增面向 `CameraFaceAlertFrame` 的推送函数，不复用、不改造 `send_external_push_alert(config, QuickAlertFrame)`，避免把识别告警塞进狼来了帧污染其文案与可信度逻辑。
- 局域网内其他接收端只展示桌宠告警，**不重复推送**，避免多设备向同一群重复推送同一事件。

## 前端改动

- 设置页人员列表：每人显示特征状态（已提取 / 未检测到人脸 / 特征不可用）。
- 摄像头监控状态区：显示识别模型就绪状态（`recognizerReady`）与错误原因；无启用人员时显示录入提示。
- `camera_face_alert_received` 监听：识别告警触发桌宠 Alert 状态并附区分标题；现有弹窗预览保留。
- 告警列表展示沿用 `personName` / `confidence`，识别告警自然显示"检测到 张三 · 87%"。
- 更新 `scripts/test-face-monitor-settings.mjs`、`scripts/test-face-monitor-media-coordinator.mjs` 等既有脚本覆盖新逻辑。

## 隐私与安全

延续现有原则：

- 采样帧与特征向量只存在于内存与本地 SQLite，不随局域网广播；广播帧只含人员名称与置信度。
- 识别模型与检测模型一样走清单 SHA-256 校验；资源目录不随 LAN 文件服务传播。
- 参考照片仍保存在 `app_data_dir/face-reference-uploads`，大小与解码校验不变。

## 测试方案

### Rust 单元测试

- 锚框解码与 NMS：单人、多人、重叠框、低分过滤。
- 对齐裁剪输出尺寸恒为 112×112；关键点缺失时的错误路径。
- 余弦相似度与 `accept_match`：不同 `personId` 独立连击与冷却。
- 特征版本不一致时重新提取；照片不可读标记"特征不可用"。
- 清单 v1 / v2 兼容解析；recognizer 校验失败时识别不可用但存在检测保留。
- 录入照片中无人脸时报错。

### 集成验证

1. 录入本人照片 → 出镜连续命中 → 产生具名告警，桌宠 Alert、外部推送文案正确。
2. 陌生人出镜 → 不产生任何告警。
3. 删除全部人员 → 不再产生任何告警，设置页显示录入提示。
4. 移除/损坏识别模型 → 状态区显示错误，不产生告警。
5. 两台设备：A 产生识别告警，B 桌宠响应但不重复推送。

## 验收标准

- 摄像头画面中的已录入人员可被自动识别并产生具名告警，告警含人员名与匹配置信度。
- 一帧多张人脸可分别识别；陌生人不误告警。
- 告警门限完全复用现有策略，无新增配置项。
- 识别告警驱动桌宠与外部推送，且文案、队列与狼来了告警明确区分。
- 无人员或识别模型异常时不产生告警事件与数据，显示错误提示，不白屏、不崩溃。
- 特征数据不出本机。
