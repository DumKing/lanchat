# LanChat 核心持久化与可选视觉能力设计

## 目标

本次改造完成四项可独立验收的产品行为，并为后续插件平台提供边界：上下线通知仅在当前运行期间展示；游戏排行榜由 SQLite 持久化且普通游戏只统计至少三名真实玩家参与的对局；用户可以删除本机与某位设备的单聊会话；流水线可以生成完全不包含视觉识别代码、命令、依赖和资源的核心安装包。

## 消息与会话

公共频道中的“某某上线了”和“某某下线了”属于瞬时在线状态，不写入 SQLite。Pinia store 新增内存系统通知入口，把消息直接合并进当前会话缓存。数据库初始化时清理历史公共频道中符合该格式的 `system` 消息，并修正会话更新时间。公告更新、消息撤回、排行榜同步等其他系统消息保持现有持久化语义。

单聊列表通过右键菜单或删除按钮提供“删除对话”。Rust 命令只允许删除 `direct` 会话，在一个事务中删除消息和会话记录。删除仅作用于本机，不删除设备、不拉黑对方；后续主动发起聊天或收到新消息时，现有的会话创建逻辑会重新建立该项。

## 游戏排行榜

新增 SQLite 表保存普通游戏累计胜负和扫雷明细，唯一键沿用现有记录 ID。前端启动时从数据库读取；旧版 localStorage 数据只迁移一次，成功写入后删除旧键。排行榜的局域网同步继续存在，收到的数据也落库。

斗地主、五子棋、象棋和大富翁只有在结束状态中存在至少三名非机器人玩家时才记入排行榜。机器人不计入门槛，也不写入玩家榜。扫雷按单人成绩记录，不受人数门槛限制。房主仍负责形成权威结算记录，幂等键防止重复计数。

## 构建级视觉裁剪

新增统一构建变量 `LANCHAT_FEATURE_VISION`。核心版默认关闭，视觉版显式开启。

前端把视觉组件、类型、API、状态、生命周期和模板移动到独立 feature 边界。Vite 在核心构建时解析到无视觉实现，编译产物不得出现视觉组件、视觉路由、视觉命令名和模型目录字符串。Rust 新增 `vision` Cargo feature；`face_monitor`、`vision`、相关 AppState 字段、命令注册、数据库结构及可选推理依赖均使用 feature 条件编译。核心 Tauri 配置不列出 `object-models` 与 `openvino-runtime`，视觉配置覆盖文件才加入这些资源。

流水线提供核心版和视觉版构建任务。核心版在打包后执行负向检查：安装包和解包目录不得包含模型、OpenVINO 动态库、视觉静态资源或已知命令字符串。视觉版继续执行现有模型与运行时测试。

## 错误处理与兼容

数据库迁移全部使用幂等 SQL。localStorage 迁移只有数据库写入成功后才删除旧数据。会话删除拒绝公共频道和私有频道 ID。核心版的前端不会调用不存在的视觉命令，Rust 也不会注册这些命令。视觉版保持当前功能和数据兼容。

## 验收

- 重启应用后历史上下线通知消失，新收到的通知在本次运行中可见。
- 两名真人加机器人结束普通游戏不计榜；三名真人结束后只统计真人；扫雷正常计榜。
- 删除单聊后会话及历史消息消失，再次收到消息会重建会话。
- 核心版通过 Rust、TypeScript 和安装包内容检查，且包内没有视觉识别代码或资源；视觉版原有视觉测试通过。
