# 超管批量远程更新设计

## 目标

让超管可以向指定设备或当前在线的全部 Windows 设备下发更新命令。默认仅更新低于目标版本的客户端；勾选强制更新后，忽略本地版本比较。携带安装包时，接收端从下发者的局域网文件服务下载；未携带时，从 GitHub Release 下载。

## 范围

- 仅对发起时在线的 Windows 设备创建命令；macOS/Linux 设备跳过并给出原因。
- 全员更新采用逐台直发，不使用会被未来上线设备接收的广播。
- 局域网包与 GitHub 包共用 SHA-256 校验、下载进度和 Windows 安装调度。
- 下载与安装结果回传给下发者，界面展示每个目标的独立状态。

## 协议

`AdminRemoteUpdateFrame` 增加：

- `force: bool`：`false` 时仅当接收端版本严格低于目标版本执行；`true` 时版本相同或更高也执行。
- `delivery_id: String`：一次批量下发的稳定批次 ID；每台命令仍有独立 `command_id`。

新增 `AdminRemoteUpdateProgressFrame`，携带命令 ID、批次 ID、阶段、已下载字节、总字节、来源与错误。阶段包括 `received`、`skipped_version`、`downloading`、`verifying`、`installing`、`failed`。成功安装会退出进程，发送端把 `installing` 视为已交接给本机安装器。

## 后端流转

1. 发送端将目标范围解析成在线 peer 快照，过滤本机和非 Windows 平台。
2. 若携带更新包，只调用一次文件服务 `share_file`，对每台生成引用同一 `FileMeta` 的命令。
3. 接收端校验目标、命令幂等和版本策略；跳过时立即回传 `skipped_version`。
4. 接收端下载时按 chunk 发进度事件与网络帧；下载来源由是否携带 `package` 决定。
5. 校验成功后回传 `verifying` 和 `installing`，再调度 EXE/MSI/ZIP 更新并退出。

## 前端

- 超管设置的远程更新卡片提供“指定设备 / 所有在线 Windows 设备”目标范围，以及“强制更新”勾选项。
- 下发后显示紧凑的逐台结果列表：昵称、IP、版本、来源、阶段、进度和失败原因。
- 接收端收到命令时自动执行，不弹出阻塞确认；在下载阶段复用应用更新进度展示格式。

## 安全与兼容

- 只接受私网 HTTP 文件地址或 GitHub HTTPS 地址。
- 局域网包必须携带 SHA-256；最大下载仍为 2GB。
- 未携带新字段的命令默认 `force = false`，统一收敛为“仅低版本更新”的安全策略；新版下发始终显式写入字段。

## 验收

- 指定目标和批量目标均会产生正确的在线 Windows 快照。
- 默认模式：低版本更新、相同或更高版本跳过。
- 强制模式：相同或更高版本仍下载并调度安装。
- 局域网与 GitHub 下载均产生可见字节进度；局域网包完成后通过 SHA-256 校验。
- 一台失败不影响同批其他目标；非 Windows 目标不发送命令。
