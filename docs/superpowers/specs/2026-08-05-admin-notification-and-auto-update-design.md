# 超管通知确认与自动更新设计

## 目标

为 LanChat 增加统一的超管通知下发能力。赞赏二维码是通知模板之一；通知可要求用户确认，并支持超管审核、截止时间和超时策略。同时为安装版与绿色版提供可校验、可恢复的强制自动更新流程。

## 范围

- 超管可向单个已发现设备下发普通通知或赞赏通知。
- 通知展示模式：可关闭、必须确认。
- 必须确认通知：用户提交确认，超管审核确认后才解除业务页面限制；被拒绝后可以重新提交。
- 截止时间和超时策略：超管手动决定、自动撤销放行、保持限制等待处理。
- 安装版自动更新：签名校验、下载、安装、重启。
- 绿色版自动更新：签名校验、下载 ZIP、由独立更新助手替换文件并重启。

不包含支付平台回调、支付金额采集、自动判定付款成功、阻止用户退出软件或操作系统。

## 通知模型

新增 `AdminNotificationFrame`，经现有 LAN 广播/直发通道传输：

- `notification_id`：全局唯一 ID。
- `target_device_id`：单设备目标。
- `title`、`content`：通知标题与正文。
- `template`：`general` 或 `support`；`support` 可包含二维码图片或链接。
- `display_mode`：`dismissible` 或 `requires_confirmation`。
- `deadline_at`：可选截止时间。
- `timeout_policy`：`manual_review`、`auto_release`、`keep_locked`。
- `issued_by_*`、`created_at`：下发审计字段。

本地 SQLite 保存通知和确认提交：`admin_notifications`、`admin_notification_submissions`。状态为 `pending`、`submitted`、`approved`、`rejected`、`revoked`、`expired_released`、`expired_locked`。

## 交互与权限

1. 超管在设备详情页填写通知并下发。
2. 目标设备接收后本地持久化；可关闭通知使用常规弹窗/通知中心展示。
3. 强制确认通知覆盖主程序业务区域，仅保留通知正文、二维码、提交确认、重新提交和退出入口。
4. 用户提交确认后，上报 `AdminNotificationSubmissionFrame` 给超管；本地保持锁定。
5. 超管在待处理列表审核通过、拒绝或撤销；结果帧回传目标设备。
6. 目标设备按截止时间执行超时策略，并记录系统事件。

通知下发、审核、撤销均须通过 Rust 侧超级管理员会话校验。不能由前端布尔参数绕过。

## 自动更新

### 共同规则

- Release 提供带签名的更新清单，包含版本、强制升级标记、最低支持版本、目标平台资产 URL、SHA-256 与 Tauri 签名。
- 客户端启动时检查；随后每天至少检查一次。
- 强制升级只在下载校验成功后触发安装；失败可重试并保留错误原因。
- 更新前保留 SQLite、桌宠资源、设置和下载缓存；替换失败回滚并重新启动旧版本。

### 安装版

接入 Tauri Updater。Windows 使用 `passive` 安装模式：显示进度但不要求用户完成安装向导。更新包必须通过内置公钥验证。

### 绿色版

新增独立 `lanchat-updater` 助手：

1. 主程序下载 ZIP 到临时目录，验证 SHA-256 与签名。
2. 写入待更新任务文件，启动更新助手并退出。
3. 助手等待主程序退出，备份当前运行目录，解压新包并替换可执行文件与资源。
4. 助手启动新版；若替换或启动失败则还原备份并重新启动旧版。

绿色版只更新程序目录，不碰用户数据目录。

## 验证

- 协议编解码与 SQLite 状态迁移测试。
- 非超管调用下发、审核命令必须失败。
- 可关闭通知可关闭；强制确认通知在审核通过、自动放行或撤销前保持业务页锁定。
- 拒绝后重新提交会生成新的提交时间，旧提交保留审计。
- 截止时间三种策略均有确定状态。
- 更新清单签名、哈希校验、失败回滚测试。
- Windows 安装版与绿色版分别验证下载、替换、重启和用户数据保留。
