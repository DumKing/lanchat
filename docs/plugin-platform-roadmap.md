# LanChat 插件平台规划

## 产品边界

LanChat 主程序长期只保留聊天、设备列表、狼来了桌宠、升级与插件管理。游戏、视觉识别以及后续业务能力通过插件安装。主程序提供稳定 API、权限控制、事件总线、存储、网络、窗口和 UI 扩展点。

## 插件形态

游戏等纯界面能力使用 Web 插件包，运行在隔离 WebView 中，通过受控消息桥访问宿主 API。视觉识别等需要本地推理的能力使用“Web UI + 签名原生 sidecar”组合包；原生代码不直接加载进主进程，降低崩溃、ABI 和升级风险。插件包包含 `manifest.json`、签名、前端资源、可选 sidecar、迁移脚本和完整性清单。

## 标准 API

第一版 API 提供设备发现只读接口、频道与单聊消息、游戏房间事件、插件私有 SQLite 命名空间、主题变量、通知、文件选择、受控网络访问、桌宠事件和日志。所有 API 带版本号，插件声明最低与最高兼容宿主版本。宿主通过 capability token 暴露授权后的接口。

## 权限和安全

权限分为设备信息、消息读取、消息发送、局域网通信、摄像头、模型下载、文件系统、通知和原生 sidecar。安装页展示权限差异；新增高风险权限必须重新确认。官方插件使用发布密钥签名，本地开发插件需显式开启开发模式。sidecar 使用独立进程、最小目录权限和带版本的 IPC 协议。

## 生命周期

插件状态为下载、校验、安装、启用、暂停、更新、回滚和卸载。安装先写入暂存目录，校验签名、哈希、权限和兼容性后原子切换。更新保留上一版本以支持一键回滚。插件数据默认保留，卸载时由用户选择保留或删除。

## 迁移阶段

1. **构建边界**：先把视觉识别变为 Cargo/Vite 可选 feature，建立无视觉核心包。
2. **宿主 SDK**：定义 manifest、API 版本、权限、事件总线、私有存储和主题协议。
3. **游戏插件**：先迁移五子棋等简单游戏，再迁移斗地主、象棋、扫雷和大富翁；排行榜由宿主服务统一提供。
4. **视觉插件**：把视觉 UI、模型管理和推理 worker 移入签名插件与 sidecar，核心程序只保留通用插件进程管理。
5. **分发中心**：提供官方目录、下载、差分更新、签名轮换、回滚和离线导入。
6. **生态开放**：发布 SDK、模板、调试工具、兼容测试套件和审核规则。

## 游戏插件接口

游戏插件声明人数、房间配置、状态同步协议、结算结构和排行榜类型。房主权威状态机继续由插件实现，宿主只负责可靠传输、房间成员、持久化排行和插件版本协商。不同版本无法兼容时禁止进入同一房间，并提供升级提示。

## 视觉插件接口

视觉插件声明摄像头、模型目录、网络下载和 sidecar 权限。宿主负责摄像头授权与帧传输，插件负责预处理、推理、匹配和模型生命周期。识别结果通过版本化事件返回，宿主的聊天和桌宠功能只能订阅经过授权的标准事件。

## 验收门槛

- 未安装插件时主程序不包含游戏与视觉业务代码或资源。
- 插件崩溃不影响聊天、设备发现和桌宠。
- 插件升级失败可回滚，数据迁移可恢复。
- 权限可审计、可撤销，禁用后相关进程、摄像头和网络访问立即停止。
- SDK 次版本保持向后兼容，破坏性变更只在主版本升级发生。
